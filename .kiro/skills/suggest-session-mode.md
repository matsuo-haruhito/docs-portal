# セッションモード提案

ユーザーのリクエストに応じて、現在のセッション（Default）でそのまま進めるか、別のセッションモードで新規に開始した方がよいかをアドバイスする。

## Kiro セッションモード一覧

| モード | 用途 |
|--------|------|
| Default | 会話ベースの汎用コーディング支援。軽微な修正、調査、質問応答 |
| Spec | 要件定義→設計→タスク分割→実装の構造化フロー。大きな機能追加向け |
| Quick Spec | 確認→requirements/design/tasks自動生成の軽量版。中規模の変更向け |
| Bug Fix | バグ調査→探索テスト→修正→検証の構造化フロー |
| Plan | 実装計画だけ作成し、コード変更は行わない |

## 判定基準

### Bug Fix を推薦する場合

- エラーメッセージや再現手順がある程度明確
- 原因箇所の特定にコード調査が必要（1ファイルのtypo修正では済まない）
- 修正後にテストで挙動を保証したい

### Spec を推薦する場合

- 新機能の追加で、要件の整理・設計判断が必要
- 複数ファイル（5+）にまたがる変更が予想される
- テーブル設計の追加・変更を伴う
- import / 外部連携 / 権限モデルに影響する

### Quick Spec を推薦する場合

- やりたいことは明確だが、タスク分割して順に進めたい
- 要件や設計の深い議論は不要
- 3〜5ファイル程度の変更規模

### Plan を推薦する場合

- 実装前に計画だけ立てたい
- 複数の選択肢を比較検討して方針を決めたい

### Default のまま進めてよい場合

- 1〜2ファイルの軽微な修正
- 調査・質問への回答
- docs / steering / skills の更新のみ
- 既に別モードで生成されたタスクの後処理

## 推薦メッセージの形式

```
これは **Bug Fix** モードで進めると品質が上がりそうです。

チャット欄右下のモード選択から **Bug Fix** を選んで新しいセッションを開き、以下のように投げてみてください:

> [投げるべきプロンプトの例]
```

## 使い方

```
このバグ直したいんだけど、どう進めるのがいい？
```

```
この機能追加、Defaultでやっちゃっていい？
```
