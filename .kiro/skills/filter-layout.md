# 検索フィルタ レイアウトガイド

## フィールド幅の基準

フィールドの値の長さに応じて列幅を決める。短い値には狭い列を割り当てる。

| 値の性質 | 推奨幅 | 例 |
|---------|--------|-----|
| 短い数値（年度、月） | 狭い | 年度、月 |
| 短い固定選択肢（2〜4件） | 狭い | 確度、有効/無効 |
| 中程度の固定選択肢（5〜10件） | 中 | 文書状態、部門 |
| 日付 | 中 | 開始日、終了日 |
| combobox（顧客、担当者等） | 中〜広 | 顧客、担当者 |
| キーワード検索 | 広 | フリーワード |
| タグ（multi_select） | 広 | タグ検索 |
| ボタン列（検索 + 解除） | auto（内容に合わせた最小幅） | — |

---

## 行分割の方針

フィルタ項目が多い場合は2行に分ける。1行に詰め込みすぎない。

### 1行目: 主要フィルタ

日常的に最もよく使う条件:
- キーワード、主要エンティティ（案件・文書）、ステータス

### 2行目: 補助フィルタ + ボタン

使用頻度が低い条件:
- 日付ペア、タグ、その他補助条件、検索/解除ボタン

---

## フィールドの並び順

### 標準の並び順テンプレート

1. **キーワード検索**
2. **主要エンティティ**（案件・文書・担当者）
3. **ステータス / 分類**
4. **日付範囲**（開始日 → 終了日をペアで並べる）
5. **補助フィルタ**（タグ等）
6. **ボタン列**（検索 + 解除 — 最終行の末尾）

### ペア配置のルール

- 「開始日」「終了日」は必ず隣接させる
- ペアは同じ幅にする（視覚的な対称性）

---

## ボタン列の標準パターン

```slim
.actions
  = f.submit "検索"
  = link_to "条件クリア", xxx_path(clear_filters: 1)
```

### ルール

- ボタン列は常にフィルタの最終行の末尾に置く
- 文言は「検索」と「条件クリア」に統一する
- ボタン列は内容に合わせた最小幅にする

---

## rfk_select / rfk_combobox の検索フィルタ内ルール

- 検索フィルタの `rfk_select` / `rfk_combobox` には必ず `allow_clear: true` を付ける
- マスタ件数が多い対象は `rfk_combobox` + `free_text: true` パターンにする
- 固定選択肢（件数少、列挙可能）は `rfk_select` で良い

---

## NGパターン

- ボタン列を1行目の途中に置く
- キーワードやcomboboxに狭い幅を使う（入力しづらい）
- 日付ペアの間に無関係なフィールドを挟む
- 解除ボタンの文言を画面ごとに変える
