# 文書詳細画面 UI/UX パイロット改善 — 実装計画

## Problem Statement

文書詳細画面（`documents/show`）を「操作マニュアルを見なくても機能を把握できる」理想形に作り込み、その過程で共通 ViewComponent 基盤を整備する。ナビゲーション構造（パンくず強化 + ページ内セクションナビ）とステータスの「次のアクション」誘導を柱として、全セクション（ヒーロー、属性パネル、コメントワークスペース）を改善する。

---

## Requirements

1. 共通基盤を先に整備: ツールチップ、PageHeader、EmptyState、StatusBadge の ViewComponent
2. パンくずリスト強化: 案件 → 文書一覧 → 文書名 → 版 の階層構造
3. ページ内セクションナビ: 「本文 / 属性 / コメント / 版一覧」のスティッキーなタブ/アンカーナビ
4. ヒーロー領域: ステータスの意味 + 次のアクション誘導をツールチップで補足
5. 属性パネル（detail_sections）の構造整理
6. コメントワークスペースの直感性改善
7. 日本語完結、アクセシビリティ準拠

---

## Background

| 項目 | 現状 |
|------|------|
| ViewComponent | Gemfile に `view_component` あり。`app/components/` 未作成 |
| パンくず | `gretel` gem あり（crumb 定義なし）。`SourcePathBreadcrumb` プレゼンターで source_path ベースの自前実装 |
| CSS | `application.css` にカスタムデザインシステム（CSS 変数、コンポーネントクラス）。Bootstrap 5.3 CDN |
| sticky 要素 | 未使用 |
| ツールチップ | steering に設計定義あり。ヘルパー・Component 未実装 |
| 文書詳細画面 | HTML 本文あり/なしで大きく分岐。`details` で属性パネルを折りたたみ |
| Stimulus controllers | 26 個。セクションナビ用は未実装 |
| 管理画面 | 30+ リソース画面。EmptyState は各画面で ad-hoc にインライン実装 |

---

## Proposed Solution

段階的に共通部品を実装し、文書詳細画面に適用する。

1. **spec で仕様を fix** → 文言・マッピング・パターンを正本として定義
2. **共通 Component 整備** → ツールチップ、PageHeader、StatusBadge、EmptyState、Breadcrumb、SectionNav
3. **文書詳細画面リファクタリング** → ヒーロー、属性パネル、コメントワークスペースに Component 適用
4. **仕上げ** → レスポンシブ、アクセシビリティ監査、docs 追加

---

## Task Breakdown

### Task 0: spec 作成（requirements.md + design.md）

**目的:** 実装判断を事前に fix し、各 Task で迷わず進められるようにする。

**成果物:** `.kiro/specs/document-detail-ux/requirements.md` + `design.md`

**requirements.md に含める内容:**
- ユーザーストーリー（internal admin / external user それぞれが文書詳細で何を確認し、何を実行するか）
- 画面状態パターン表（HTML本文あり/なし × 版あり/なし × 権限ロール）
- 各状態で「見えるべきもの」「操作できるべきもの」「隠すべきもの」の定義

**design.md に含める内容:**
- ステータス → バッジ色 → tooltip テキストのマッピング表
- セクションナビ構成（画面状態別に表示するタブの組み合わせ）
- パンくず階層定義（ロール別・画面別）
- ツールチップ配置箇所と文言リスト（操作ボタン、ステータス、セクション見出し）
- EmptyState パターン（セクション別の heading + description + 推奨アクション）
- Component の slot / props 設計

**Demo:** spec ファイルが完成し、以降の Task はこれを正本として参照しながら実装する。

---

### Task 1: ViewComponent 基盤セットアップ + ツールチップコンポーネント

**目的:** `app/components/` を立ち上げ、ツールチップ（info_tooltip / help_tooltip）を ViewComponent + ヘルパーとして実装する。

**実装ガイダンス:**
- `app/components/` ディレクトリ作成
- `InfoTooltipComponent` / `HelpTooltipComponent` 実装（CSS-only のホバー/フォーカス表示）
- `ApplicationHelper` に `info_tooltip(label, text)` / `help_tooltip(text)` ヘルパー追加
- `tabindex="0"` + `aria-label` でアクセシビリティ対応
- ツールチップ用 CSS を `application.css` に追加

**テスト:**
- Component の unit test（render して期待する HTML 構造を確認）
- ヘルパーの unit test

**Demo:** 任意のビューで `= info_tooltip "見出し", "補足説明"` と書くとホバー/フォーカスでテキストが表示される。

---

### Task 2: PageHeaderComponent 実装

**目的:** 画面タイトル、サブタイトル、パンくず、アクションボタンを統一的に描画する。

**実装ガイダンス:**
- `PageHeaderComponent` 作成（slots: title, subtitle, breadcrumbs, actions）
- 既存の `.page-hero` CSS を基盤に整理
- パンくずは `breadcrumbs` slot で配列を受け取り `nav[aria-label="パンくず"]` として描画

**テスト:**
- 各 slot の有無でレンダリングが変わることを確認

**Demo:** `= render PageHeaderComponent.new(title: "文書名")` で画面ヒーローが統一的に描画される。

---

### Task 3: StatusBadgeComponent + EmptyStateComponent 実装

**目的:** ステータスバッジ（色 + テキスト + ツールチップで「次のアクション」を伝える）と、データ 0 件時の統一案内。

**実装ガイダンス:**
- `StatusBadgeComponent`: status, label, tooltip を受け取り描画。色は status 値に応じた CSS class
- `EmptyStateComponent`: heading, description, actions(slot) を受け取り描画
- 既存 `.badge` / `.empty-state` CSS を基盤に

**テスト:**
- 各パターンの出力確認
- tooltip あり/なしの分岐確認

**Demo:** `= render StatusBadgeComponent.new(status: :published, label: "公開済み", tooltip: "社外ユーザーに表示されています")` でツールチップ付きバッジが表示される。

---

### Task 4: パンくずリスト強化（BreadcrumbComponent）

**目的:** 案件 → 文書一覧 → 文書名 → 版 の階層を統一的に描画する。

**実装ガイダンス:**
- `BreadcrumbComponent` 作成。crumbs 配列（label, path）を受け取り `nav > ol` で描画
- 既存 `SourcePathBreadcrumb` を活用しつつ、上位階層（案件→文書一覧）を追加
- `aria-label="パンくず"` + 最終要素に `aria-current="page"`
- CSS: `.breadcrumbs` をセパレーター + 現在位置強調に整備

**テスト:**
- 階層の深さに応じた出力確認
- ロール別のリンク先確認

**Demo:** 文書詳細画面上部に `プロジェクトA > 文書一覧 > 設計書` のパンくずが表示される。

---

### Task 5: ページ内セクションナビ（SectionNavComponent + Stimulus controller）

**目的:** 文書詳細画面のヒーロー下に「本文 / 属性 / コメント / 版一覧」のスティッキーなタブ/アンカーナビを実装する。

**実装ガイダンス:**
- `SectionNavComponent` 作成。sections 配列（label, anchor_id, badge_count?）を受け取り描画
- CSS: `position: sticky; top: 0; z-index: 10;`
- Stimulus controller `section_nav_controller.ts`: IntersectionObserver で現在セクション検知 → `is-active` class 付与
- スムーススクロール（`scroll-behavior: smooth`）
- アクセシビリティ: `role="tablist"` + `aria-controls`

**テスト:**
- Component の出力確認
- Stimulus controller の接続テスト

**Demo:** スクロールするとヒーロー下に固定ナビが現れ、現在位置に応じてハイライトが追従する。タップでスムーススクロール。

---

### Task 6: 文書詳細画面のヒーロー領域リファクタリング

**目的:** `documents/show.html.slim` のヒーロー領域を Component で書き直し、「今何が見られて、次に何ができるか」を一目で伝える。

**実装ガイダンス:**
- `PageHeaderComponent` でタイトル + パンくず + アクション描画
- 最新版ステータスを `StatusBadgeComponent` で表示
- HTML 本文有無をアイコン or ステータスで視覚的に伝える
- 操作ボタンに `help_tooltip` で用途説明
- design.md のマッピング表を正本として文言を設定

**テスト:**
- 既存 request spec が全パス
- 新規: ステータス別の表示パターン確認

**Demo:** ヒーロー部分が PageHeader に統一。ステータスバッジにホバーで「この版は公開済みです」、操作ボタンにもツールチップで案内が出る。

---

### Task 7: detail_sections（属性パネル）の構造改善

**目的:** 折りたたみ一括の `details` から、構造的なセクション別カードに再構成する。

**実装ガイダンス:**
- `details.document-context-drawer` を廃止 → セクション別カード（属性、版一覧、関連文書、確認依頼）
- 各セクションに `id` 付与でセクションナビと連動
- 属性は `dl.definition-list` で統一
- 版一覧: `StatusBadgeComponent` + ツールチップ
- 関連文書 / 確認依頼: `EmptyStateComponent` で 0 件案内
- `info_tooltip` を適用: カテゴリ、重要度、公開範囲、出力時の扱い

**テスト:**
- 既存 request spec パス
- EmptyState 表示パターン確認

**Demo:** 属性パネルがカード形式に分離。スクロールでセクションナビがハイライト。0 件時は EmptyState 表示。

---

### Task 8: コメントワークスペースの直感性改善

**目的:** floating FAB の UX 改善、未解決件数の視覚的強調、タブの意図をツールチップで説明する。

**実装ガイダンス:**
- FAB に未解決件数バッジ（数字）を重ねて表示
- タブ（すべて / Q&A / 確認事項 / 未解決）に `info_tooltip` で用途説明
- モード切替（質問/確認事項）に `help_tooltip` で違い説明
- セクションナビ連動: `id="comments"` 付与
- 0 件: `EmptyStateComponent` で案内

**テスト:**
- コメント投稿の既存 request spec パス
- FAB バッジの表示確認

**Demo:** FAB に未解決件数バッジ。タブにホバーで説明。0 件時は EmptyState で次のアクション案内。

---

### Task 9: スタイル統合 + レスポンシブ + アクセシビリティ監査 + docs

**目的:** 全 Component の CSS 統合、レスポンシブ確認、アクセシビリティ監査、ドキュメント追加。

**実装ガイダンス:**
- セクションナビのモバイル対応（横スクロール）
- ツールチップのモバイル対応（タップで表示/非表示）
- パンくずの省略対応（`text-overflow: ellipsis`）
- フォーカス管理確認（タブキーで全操作可能か）
- `aria-label`, `role`, スキップリンク確認
- 既存テストスイート全体で regression なし確認
- `docs/` に UI/UX パイロット設計メモ追加（横展開の参考）
- `docs/README.md` の索引更新

**テスト:**
- `bundle exec rspec` 全パス
- slim_lint パス

**Demo:** モバイルでもセクションナビが使え、ツールチップがタップ表示。全テスト green。文書詳細画面が「初見で迷わない」状態になっている。
