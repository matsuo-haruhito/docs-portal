# Canonical UI tokens and scoped shell styling

This change introduces the canonical `--ui-*` palette, retains old tokens as migration aliases, and moves shell styling from bare `header`/`main` selectors toward component classes. Public navigation, admin layout, cards, badges, and column settings move to neutral surfaces without changing business views, authorization, RTP/rfk/tree_view wiring, table keys, or persistence contracts. **Watch for:** **confirmed** production CSS extraction does not preserve the intended Bootstrap-first ordering; **confirmed** responsive rules still target every `main` element.

**Verdict**: NEEDS_CHANGES

## High-level view

The reordered JavaScript imports do not establish the intended cascade boundary. A production Vite build emits `application.css` before `bootstrap_overrides.css`, leaving Bootstrap's generic `.button` declarations later than product component declarations.

The main-shell scope conversion stops at the desktop rule. Below 960px, bare `main` width and margin rules still reach `.admin-main` and any future semantic main region.

## Vite extraction defeats the Bootstrap-first cascade

`application.js` imports `bootstrap_overrides.css` before `application.css`, but the production manifest generated from the reviewed worktree lists the relevant assets as:

```text
admin_layout-*.css
application-*.css
bootstrap_overrides-*.css
user_navbar-*.css
```

This ordering is **confirmed** in `public/vite/.vite/manifest.json`. Because Vite emits these stylesheets as separate CSS chunks, JavaScript import position is not a durable cascade guarantee. The later `.button` rule in `bootstrap_overrides.css` supplies the final background, color, display, padding, and border from Bootstrap variables; `.button.secondary` therefore resolves to the Bootstrap secondary treatment rather than retaining the neutral product declaration in `application.css`. The new `:not(:where(...))` selector fixes the reported danger-button specificity conflict, but not asset order.

Make the order explicit at the CSS bundling boundary and validate the emitted manifest or final bundle. Otherwise low-specificity component styles can pass source guards and selected screenshots while being replaced in production.

## Responsive `main` leakage remains after desktop scoping

The desktop container changes from bare `main` to `.app-main`, but the 960px media query still contains `main, .layout-with-sidebar { width: calc(100% - 32px) }` and `main { margin: 24px auto }`. This is **confirmed** to match `main#main-content.admin-main` as well as both public main variants. `.admin-main` wins the margin through higher specificity but does not reset width, so public sizing still crosses the shell boundary on narrow admin viewports not covered by the 1440px smoke.

Target `.app-main` and `.main-panel` explicitly to complete the bare-element scope migration.

</details>
