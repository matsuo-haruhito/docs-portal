# 監査ログの50件表示・200件出力分離と一括編集の長大画面整理

監査ログのHTML一覧を1ページ50件へ縮小しつつ、通常CSVとmetadataは条件一致の最新200件、明示的なcurrent-page出力は表示中の50件に分離しています。低頻度filterと補助exportはDisclosureへ移し、一括編集では既存form内の対象表をスクロール領域化して技術JSON導線を閉じています。認可、filter param allowlist、RTP table key、checkbox payload、handoffの50件上限は変更されていません。

## High-level view

監査ログは`ACCESS_LOGS_PER_PAGE = 50`と`ACCESS_LOGS_EXPORT_LIMIT = 200`を分け、HTML/current-pageとlatest exportを同じfiltered scope上で分岐しています。最大ページは`10_000 / 50 = 200`で、最終ページのoffsetは9,950、それより大きいpage値は1ページ目へ正規化されます。

常設filterは操作・対象種別・案件だけになり、残りは同じGET form内のnative detailsへ移っています。latest CSVはDisclosure外、current-page CSVと2種類のmetadataは初期closedのDisclosure内にあり、pageとscopeの有無が役割ごとに分かれています。

一括編集の対象表はformとStimulus controllerの内側に残したまま、縦450pxのフォーカス可能なscroll regionになっています。checkboxの`bulk_edit[document_ids][]`とhandoff endpointの先頭50件への切り詰めは既存contractを維持しています。

## 監査ログのHTML/current-page 50件とlatest 200件の分離

`paginated_access_logs`は次ページ判定用の1件を加えて取得し、HTMLは50件へ切り詰めます。`csv_access_logs`は`csv_scope=current_page`のときだけ同じoffsetと50件limitを使い、通常CSVはpage paramを無視して最新200件を取得します。metadataのrow limit、page属性、description、summaryも同じscope判定を使っています。

`ACCESS_LOGS_MAX_ROWS = 10_000`から200ページを導出し、`page_param`は1..200だけを許可します。200ページ目では次ページを出さず、任意の`limit` paramはpermitもquery構築もされないため、10,000行到達境界と1応答の件数境界は広がりません。

## 監査ログfilter・認可・RTP contractを保ったDisclosure再配置

controller差分はページ・export件数定数と参照先に閉じており、`before_action :require_admin_only!`と`filter_params`のpermit項目は変更されていません。viewの`table_key = :admin_access_logs`、`ColumnSettingsComponent`、`table_preferences_table_tag`、column keyも維持されています。

高度条件の`details.filter-details`は検索用`form_with`の子孫で、正規化済みの高度filterが有効なら`open`で再描画されます。export補助は検索formの外にあり、latest CSV linkだけがDisclosure外かつpage/scopeなし、current-page CSV/metadataだけが現在のpageと`csv_scope=current_page`を持ちます。

## 一括編集のscroll regionと技術JSON handoff

scroll wrapperは既存form内でtableだけを包み、checkboxのname、value、checked判定、Stimulus target/actionを変更していません。画面内検索は行の`hidden`状態だけを変えるため、非表示のchecked checkboxもsubmit対象に残ります。

技術JSON buttonも同じform内で、`formaction`と`formmethod=post`によりhandoff endpointへ分岐します。server側の`BULK_EDIT_CANDIDATE_LIMIT = 50`、ID正規化、先頭50件への切り詰め、`truncated`算出に差分はありません。
