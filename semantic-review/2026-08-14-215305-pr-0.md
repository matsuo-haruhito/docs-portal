# Wave 1通常HTML画面のSlim移行

対象5画面は同名ERBを削除してSlimへ移され、helper、block、route、params、条件分岐、DOM属性、Turbo指定を維持しています。HEADとの差分に見える「ホーム」「保存済み」、固定panel IDの`aria-controls`、フィルタ見出し・badge整理は、現行の未コミットCSS・仕様・request specが要求する変換前UI契約と一致しており、Slim化によるドリフトではありません。指定5文書は現行実装パスの拡張子だけを更新し、対象旧ERBパスはdocs/specに残っていません。

## 未コミットUI契約とHEAD差分の切り分け

Git上の旧ERBだけを基準にすると、ダッシュボードの値span、案件一覧の「ホーム」、保存済み画面のタイトル・フィルタ・badge・tooltipが追加変更に見えます。しかし、これらは同じworktreeの未コミットCSSと現行仕様に対応し、保存済み画面の固定panel ID、見出し、badge非表示、tooltipはrequest specでも構造的に固定されています。変換前の未コミット実装を維持する依頼条件に照らし、Slim化の回帰とは判定しませんでした。

## 検証境界

対象を直接参照するsource specにERB拡張子やERB構文の固定はなく、更新は不要です。旧対象パスの横断検索は0件で、限定パスの`git diff --check`にも問題はありません。Slim静的コンパイルの通過は委譲時情報として確認し、request specはユーザー指定どおり実行していません。
