# AccessibleDocuments の検索結果メタ情報とRTP表示改善

Phase 3 の `/documents` UI sliceは、検索・認可・URL契約を変えず、件数、複数ページ時のページャー、列設定を同じlist meta領域へ集約しています。`match_reason` は検索語が空なら初期非表示、検索語があれば初期表示となり、保存済みRTP設定は引き続きその初期値より優先されます。RTPのscroll wrapperへ横スクロール領域を委譲し、最終更新は短縮表示しながら完全値を`title`に保持しています。重大・中・軽微のいずれにも指摘はなく、指定された契約にblocking regressionは見つかりませんでした。

Watch for: blocking concernなし。`list-meta`は現時点でAccessibleDocumentsだけが使用しており、汎用名による既存画面への実影響もありません。

**Verdict**: APPROVED

## High-level view

`GET /documents`、`/documents/project_search`、`/documents/selected_project`と、案件・文書への公開側リンクは変更されていません。controller、routes、request specsも差分外で、検索結果とremote pickerは従来どおり公開可能文書から導出されます。

一覧の母集団は引き続き`Document.portal_visible_to(current_user)`です。internalのinternal-only可視性、externalの案件所属とuser/company permission、published statusと公開期間の判定はmodel concernに残り、今回のview/helper変更はこの境界を迂回しません。

RTPは`accessible_documents`と12個のstable keyを維持しています。検索語による`match_reason`のdynamic defaultは未保存時だけに作用し、gemのsettings mergeでは保存済み`visible`がdefaultを上書きします。

filter allowlist、20件単位、全filter paramを引き継ぐpager、page clampは変更されていません。基本3条件と追加条件Disclosureの配置、有効なadvanced enum/boolean条件だけで開く判定も維持されています。

list metaは0件では件数だけ、1ページでは件数と列設定、複数ページでは件数・pager・列設定を近接表示します。RTP wrapperがcaptionを含むtable全体をfocus可能な横スクロールregionで包み、短縮日時には完全日時が`title`として残ります。

## URLと公開文書導線の不変性

一覧フォームは`documents_path`へのGET、案件pickerは`project_search_documents_path`と`selected_project_documents_path`を継続利用しています。結果行は案件を`project_path(document.project)`、文書を`project_document_path(document.project, document.slug)`へリンクし、DB連番を公開文書URLへ持ち込んでいません。既存request specはremote searchをportal-visibleな案件に限定し、selected restoreが不可視案件や未知IDを返さないことをカバーしています。

## portal_visible_toを起点とする認可境界

AccessibleDocumentsControllerは`Document.portal_visible_to(current_user)`へproject、keyword、tag、enum、availability filterを適用し、project候補も同じscopeの`project_id`から作ります。picker経由で一覧認可を広げる経路はありません。

`portal_visible_to`はinternalにはactive document、externalには案件アクセス、internal-only除外、public-with-loginまたはuser/company permissionを要求します。さらに版なし文書、または公開中かつ現在が`published_from`/`published_until`内の版を持つ文書へ限定します。この実装とmodel/request coverageは差分外です。

## dynamic match_reasonと保存済みRTP設定

12列とkeyは不変で、`match_reason`列もheader/cellを含め常にDOMへ残ります。変更は`default_visible`へ`@filters[:q].present?`を渡す点だけで、空文字・空白のみはhidden、実検索語はvisibleです。match summaryは`DocumentSearch#match_summaries_for`へ到達し、既定上限`MATCH_SUMMARY_LIMIT = 3`を維持しています。

RTP controllerはcolumn metadataからdefault settingsを作り、保存済みcolumn設定をkey単位でmergeします。`visible: savedColumn.visible ?? defaultColumn.visible`のため、保存済み表示・非表示が検索語の有無より優先され、keyword-aware defaultは未保存利用者だけに作用します。

## filter、pagination、Disclosureの連続性

`DocumentsParameter::INDEX_FILTERS`は`q/tag/category/document_kind/visibility_policy/has_html/has_files/has_pdf/has_diagram/page`を維持し、controllerは従来どおり`project_id`も許可します。`DOCUMENTS_PER_PAGE = 20`、下限1へのnormalize、総ページ超過時の最終ページclampも差分外です。pagerは`@filters`からpageだけを除くため、全filter parameterを前後リンクへ保持します。

Disclosureの外側にはq、project_id、tag、内側にはcategory、document_kind、visibility_policyと4つのhas_*が残ります。open条件も有効なenum値またはtrueへcastされたhas_*だけで成立し、基本条件だけでは開きません。

## list meta、scroll region、日時表示

件数、pager、ColumnSettingsはtable直前の同一flex領域へ移動しました。pagerは`@total_pages > 1`の場合だけ、ColumnSettingsは結果がある場合に表示され、0件時はtableと列設定を出しません。

RTPの`scroll_wrapper: true`へ`table-scroll`、`role="region"`、`tabindex="0"`、検索結果のaria-labelを渡しています。gemはhost classを標準wrapper classへ併合し、tableにcontroller dataを残すため、横スクロール、focus outline、caption、RTP操作が共存します。

`updated_at`は`%m/%d %H:%M`へ短縮され、cellの`title`には`%Y-%m-%d %H:%M`を保持します。列metadataの`overflow: :ellipsis`によりwidth 130px、nowrap、ellipsisが適用されます。`sortable: true`とstable keyは不変です。

## list-meta CSSの影響範囲

追加selectorは`.list-meta`とその3つの要素classに限定されています。現行app内の利用はAccessibleDocumentsだけで、管理画面の`.admin-list-meta*`とは一致せず、bare elementや既存component selectorも上書きしません。
