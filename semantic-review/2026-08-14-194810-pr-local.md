# 保存済みタブの固定ARIA参照と表示ノイズ削減

Phase 3の「保存済み」sliceは、各tabの`aria-controls`を固定panel IDへ対応させ、active viewだけをSSRする契約をrequest specで明示します。画面用語を「保存済み」へ揃え、filter見出しを16pxへ縮め、tabで判別できる対象badgeと全行同一badgeを削除します。controller、model、routes、pagination、認可、mutation、maintenance境界は変更されていません。ただし、recent badgeが担っていた20件上限の説明まで消え、通常の結果あり状態では一覧がboundedであることを判断できなくなっています。

Watch for: **[中][confirmed]** recent一覧から「表示中最大20件」の説明がなくなり、20件を超える履歴が存在しても画面上は全件表示に見えます。

**Verdict**: NEEDS_CHANGES

## High-level view

favorite / read_later / recentはそれぞれ固定panel IDを参照し、応答にはactive panelだけが存在します。選択tabだけが`tabindex="0"`となり、共有Stimulus controllerによる矢印、Home / End、Spaceのmanual activationも維持されます。

`view`、`project_code`、`bookmark_q`、`recent_q`、`favorite_page`、`read_later_page`の引き回しは差分外です。favoriteとread_laterは独立した20件pagination、recentは`RecentDocumentsQuery`の最大20件を維持しています。

一覧と案件selector候補は`current_user.document_bookmarks`と`readable_by(current_user)`の範囲に閉じ、recentもcurrent userと閲覧可能文書だけを対象にします。remote search / selected endpointは追加されず、不可視文書や案件情報を返す新経路はありません。

createは文書`public_id`、move/destroyはbookmark `public_id` routeを継続します。favoriteは解除、read_laterは移動と解除、recentは読み取り専用で、`READ_ONLY_MAINTENANCE`中のmutation停止、一覧閲覧、navigation fallbackも不変です。

favorite / read_laterの対象badgeと各行の同一badgeはtab名・panel見出しと重複しています。「お気に入りにも保存中」は行ごとの条件付き情報として残りますが、recent badgeに含まれていた20件上限だけは代替表示がありません。

## recent 20件上限の表示情報が失われる

**[中][confirmed]** 変更前のrecent panelには`対象: 最近見た文書（表示中最大20件）`があり、対象名だけでなくbounded listであることを常時伝えていました。変更後は見出しが`最近見た文書 N件`、tab countも`N`だけで、20件ちょうど表示されたときに21件目以降が存在し得ることを示す表示がありません。「最大20件」は検索0件時の説明にだけ残るため、通常の結果あり状態では到達できません。

対象名はtabとpanel見出しで重複するため削除対象ですが、上限は重複情報ではありません。recent見出しまたは件数の`InfoTooltipComponent`等へ「最近表示された文書を最大20件表示します」を移せば、generic badgeを復活させず情報密度とキーボード・支援技術向け説明を両立できます。

## 固定ID tabと状態保持

`panel_ids`は3 tabを固有IDへ固定し、active sectionの`aria-labelledby`は対応tabへ戻ります。request specは固定対応、roving tabindex、active panelの存在、inactive panelの不在をまとめて検証しています。共有`server-rendered-tabs` controllerとそのbehavior specは差分外で、manual activation契約を保持します。

保存済みfilterはactive viewとrecent query、recent filterはactive viewと保存済み側filterを保持します。tab、pager、move/destroy fallbackは両pageを含む6 parameterを引き回します。`SAVED_BOOKMARKS_PER_PAGE = 20`、page clamp、`RecentDocumentsQuery.new(user: current_user, limit: 20)`はいずれも差分外です。

## 認可・mutation・maintenance境界

favorite / read_later relationと案件候補はcurrent userのreadable bookmarkから導出され、recent queryもcurrent userのview logを閲覧可能文書へ限定します。routeは`resources :document_bookmarks, param: :public_id`、create payloadもdocument `public_id`のままです。既存specは不可視文書除外、他ユーザーbookmarkの404、不可読文書create/move拒否、重複防止、既存favoriteとのmergeをカバーしています。

`READ_ONLY_MAINTENANCE` gateはcreate / move / destroyのDB変更前に残り、maintenance specは一覧200、mutation不発、filter/page付きfallbackを検証します。今回のmaintenance spec変更はページ用語の期待値だけです。

## CSS、用語、検証

`.bookmark-filter__heading`はclass scopeで`font-size: 1rem`、`line-height: 1.4`、下marginだけを指定し、saved filterの`h2`とrecent filterの`h3`へ適用されます。`page_title`は画面`h1`とuser navbarに合わせて「保存済み」になります。
