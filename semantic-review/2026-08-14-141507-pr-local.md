# Diagnosticsへ直結する管理概要の要対応カード

Phase 3管理概要sliceは、設定診断・文書実体欠落・継続失敗候補のカード全体をDiagnosticsの対応セクションへリンクし、件数に応じたzero / warning / danger表現を追加します。最近の運用失敗が0件のときは大きなempty stateをcompactな正常表示へ置き換えます。Controller集計、認可、主要データ、recent件数制限、Diagnosticsのread-only処理は変更されず、前回APPROVED済みのPhase 1 CSSは対象から除外しました。Watch for: no blocking findings in the scoped hunks.

**Verdict**: APPROVED

## High-level view

各要対応カードは単一のblock linkになり、表示ラベルと件数を含むaccessible name、カード内に収まる`:focus-visible` outlineを持ちます。nested interactive contentはなく、compact stateのcheck iconも装飾扱いです。

設定診断はerrorをdanger、warningのみをwarning、文書実体欠落をdanger、継続失敗候補をwarningとして分類します。項目名と件数を常時表示し、0件も数値と文言で示すため、異常の有無は色だけに依存しません。

Diagnostics側は既存sectionへのID追加に留まり、GETの診断・集計処理と`require_admin_only!`境界を保持します。`company_master_admin`はDashboard controllerで専用テンプレートへ分岐するため、今回のinternal admin向けカードやDiagnosticsリンクは表示されません。

## カードリンクのHTML semanticsとkeyboard focus

各`article`内のinteractive contentは、`h3`と件数を包含する1つの`a`だけです。`aria-label`は対象名・件数・遷移目的を伝え、全面リンクはキーボードで1回だけフォーカスします。親の`overflow: hidden`に対してoutlineを内側へ描画するためfocus indicatorはclipされず、最近の運用失敗0件表示もiconではなく「最近の運用失敗はありません」というテキストで状態を伝えます。

## 業務severityと非色覚依存の状態表現

設定診断はerrorが1件でもあればdangerを優先し、errorなしでwarningがあればwarningになります。文書実体欠落は整合性異常としてdanger、継続失敗候補は通知済み・確認済み・自動復旧を保証しない観測候補としてwarningに留め、Diagnosticsの説明と整合します。zero / warning / dangerの全状態で項目名と件数が残るため、色は優先度の補助に限定されています。

## Fragment anchorとsticky header

`#failures`、`#configuration`、`#document-files`はDiagnosticsの業務セクションに対応し、app配下に重複IDはありません。`.diagnostic-section`の`scroll-margin-top: 5rem`は約45pxのsticky admin headerを超える退避量を確保します。リンクはfilter parameterなしの通常GETなので、設定診断の表示行を意図せず絞り込まず、fragmentもserver-side処理を変更しません。

## company_master_adminとDiagnostics read-only境界

`Admin::DashboardController#index`は`company_master_admin?`を専用テンプレートへ分岐させるため、変更した`index.html.slim`はinternal adminにだけ描画されます。Diagnosticsは引き続き`before_action :require_admin_only!`で保護されています。今回追加されたのはGETリンクと既存sectionのIDだけで、mutation、retry、ack、cleanupの経路はありません。

申告済みのVite build、diff check、entrypoint guard、request spec 18件、1440px / 900px overflow、各カードのtarget・hash・viewport到達確認に加え、本レビューではDashboard / Diagnostics controller、admin shellのsticky header、company master admin分岐を確認しました。
