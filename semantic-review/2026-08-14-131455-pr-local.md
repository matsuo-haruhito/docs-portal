## Bootstrap boundary is fixed inside the application stylesheet

`application.css` imports `bootstrap_overrides.css` before product tokens and component rules, and `application.js` no longer imports the override separately. The production build succeeds, and the JavaScript entry's manifest CSS array contains `application-DXzIbq8e.css` without `bootstrap_overrides-DoEQdvdW.css`. This resolves the previous **confirmed** ordering finding: Vite can no longer link the override chunk after product component CSS.

The imported boundary can safely reference `--ui-*` properties declared later because custom properties resolve at computed-value time. Product declarations retain precedence over the generic Bootstrap-compatible baseline, while the danger focus ring and later danger colors remain effective.

## Public responsive sizing no longer reaches the admin shell

Both declarations in the 960px media query now target `.app-main` rather than semantic `main`. The desktop and responsive rules address the same public hook added in `application.html.slim`; `.admin-main` retains `margin: 0`, unconstrained width, transparent background, and admin padding. This resolves the previous **confirmed** cross-shell leakage.

## Accessibility and internal UI gem boundaries

The text-input selector excludes submit, button, reset, checkbox, and radio controls. Tom Select's internal spacing resets remain `!important`, with the dedicated override asset loaded later; RTP controller registration, metadata, editor markup, and tree_view stylesheet loading are untouched.

Measured contrast is 5.87:1 for action text on action-soft, 4.76:1 for muted text on white, 6.47:1 for danger text on white, and 10.30:1 for header links on the page-header surface. Existing focus-visible treatment remains on application and danger buttons, search inputs, column settings, and navigation dropdown summaries.
