# Phase 3 文書権限一覧の高密度UI・アクセシビリティ整備

文書権限のAssignments / Overview構成を維持したまま、検索領域を共通toolbarへ寄せ、列設定をlist metaへ移し、各表へ横スクロール領域とcaptionを追加しています。行操作は対象文書・付与先・権限を含むアクセシブルなicon-only操作へ置き換えられ、削除確認も対象行の文脈を保持します。controller、routes、CSV生成、認可、maintenance gateは変更されておらず、既存の回帰specと今回追加されたDOM契約specで境界が維持されています。

Watch for: blocking concernなし。指定されたtable identity、単一SSR tab、filter / pagination / CSV、public_id、認可、RTP / accessibility契約はすべて**confirmed**です。

**Verdict**: APPROVED

## High-level view

Assignmentsは`admin_document_permissions`と5個のstable key、Overviewは`admin_document_permission_overview`と7個のstable keyをそのまま使用しています。幅調整はmetadataだけに限定され、保存済みRTP設定を識別するtable keyやcolumn keyは変えていません。

各tabの`aria-controls`はそれぞれの固定panel IDを指し、request時には選択中viewのtabpanelだけを描画します。inactive tabの固定参照とactive panelのみSSRする契約をrequest specが直接検証しています。

検索フォームは既存の`project_id`、`q`、`access_level`、`target_type`を同じGET parameterで送信し、pagination linkはfilterとviewを保持します。CSV linkはfilterだけを引き継ぎ、pageとviewを除外するため、固定13列・全filtered rowsという既存export境界を保ちます。

行操作はpublic_id member routeへ解決され、編集・削除のaccessible nameとtitleに対象行の文脈が含まれます。admin-only before actionと`READ_ONLY_MAINTENANCE`中のcreate / update / destroy gateはcontroller側に残り、read-onlyの一覧・CSV・検索導線にも変更はありません。

## RTP identityを維持した表示密度調整

Assignmentsは`document`、`company`、`user`、`access_level`、`actions`、Overviewは`document`、`project`、`visibility_policy`、`company_permissions`、`user_permissions`、`view_allowed`、`download_allowed`をhelper metadataと`th` / `td`の両方で維持しています。変更は長文列の固定幅を外すことと短文列の幅調整に限られ、`pinned`、ellipsis、sortable metadataも変えていません。

ColumnSettingsをlist metaへ移しても、選択中tabかつ行が存在する場合だけ、そのtabと同じtable key、columns、settingsを持つeditorを描画します。

## 固定tab relationと単一panel SSR

Assignments tabは`document-permissions-assignments-panel`、Overview tabは`document-permissions-overview-panel`を常に参照し、tabpanelの`aria-labelledby`は対応するtab IDへ向きます。更新されたrequest helperは固定mapping、`aria-selected`、roving `tabindex`、active panelの存在、inactive panelの不在をまとめて検証します。

## Filter、25件pagination、固定13列CSVの分離

`rfk_search_field :q`への置換後もparameter名は`q`で、案件、権限、付与先も既存名を維持しています。検索formのhidden `view`と、`@filters.compact.merge(view: @view)`から作るpage linkによりtabとfilterを保持し、共通paginatorの既定25件を使用します。

CSV linkは`@filters.compact.merge(format: :csv)`から作るためfilterを反映し、pageとviewは含みません。CSV actionはpaginated relationではなくfiltered relationを使い、`DOCUMENT_PERMISSIONS_CSV_HEADERS`の13列を維持しています。

## public_id行操作とmutation boundary

編集・削除pathは`permission`から`:public_id` member routeへ解決されます。各操作は対象文書・付与先・権限を含む`aria-label`と`title`を持ち、iconを`aria-hidden`、補助テキストをvisually hiddenとし、削除formへ対象行固有の`data-turbo-confirm`を付けます。

`require_admin_only!`は全actionに適用され、maintenance modeではcreate / update / destroyだけを停止します。company master admin / external拒否と、maintenance中も一覧・Overview・CSV・remote searchを許可する既存specは変更後も成功しています。

## RTP scroll wrapperとtable labeling

両tableは既存採用済みのgem option `scroll_wrapper: true`を使い、wrapperへ`role="region"`、`tabindex="0"`、表ごとの`aria-label`を渡します。visually-hidden captionをtable自体にも置き、RTP controllerや保存契約へ独自処理を加えていません。

## Regression evidence

Docker上でsource spec、主要request spec、pagination、CSV本体、CSV link、案件filter、empty-state clear link、maintenance mode、company master admin境界を実行し、43 examples / 0 failuresでした。ホスト実行はPostgreSQL socket不在でspec読込前に停止したため、起動済みcompose環境で検証しています。browser visual evidenceは取得していません。
