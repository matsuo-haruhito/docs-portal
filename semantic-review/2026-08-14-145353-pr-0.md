# 運用・診断の優先度別サマリーとセクション導線

Phase 3は、Diagnosticsを「要対応」から始まる運用順へ並べ替え、設定不備・文書実体欠落・継続失敗候補を集約して6セクションへの導線を追加します。モデル観測は全33カードをnative Disclosureへ移し、モデル数・全体の最終更新・Model Browser導線を常時表示します。controller、`require_admin_only!`、候補抽出、digest、storage内訳、filter、遷移先は変更されず、追加表示もread-onlyです。ただし、新しいadmin利用ではSectionNavのARIAモデルとsticky offsetに解消すべき問題があります。

Watch for: **confirmed** — SectionNavは全セクションを同時表示するページ内リンクなのに`tablist`/`tab`/`aria-selected`として公開されます。**confirmed** — admin header下でSectionNavクリック時のオフセットがnav自身の高さしか引かず、targetがsticky navに重なります。

**Verdict**: NEEDS_CHANGES

## High-level view

認可とread-only境界は既存Diagnostics controllerに残り、今回のview追加から状態変更は発生しません。モデルブラウザを含む遷移先も既存admin-only gateのままです。

先頭の合計は、設定warning/errorのcheck数、欠落ファイル数、3系統の継続失敗identity候補数を「確認候補」として足したtriage値です。内訳カードが単位を分けて表示するため、合計の意味は追跡できます。

モデル詳細はclosedなnative `details`内へ移動するため、33カードはDOMとキーボード導線に残ります。概要値とModel Browser導線はDisclosure外です。

Optional `aria_label`は既定値を維持し、既存呼び出しとの互換性があります。neutral/action tokenへの変更は共有SectionNav全体へ及びますが、同componentのsurface、hover、focus、active表現に閉じています。

## ページ内ナビゲーションをタブとして公開している

**confirmed:** Diagnosticsでは6セクションが同時表示され、SectionNavはパネルを切り替えずアンカー位置へスクロールします。一方、`app/components/section_nav_component.html.slim:1-3`は`role="tablist"`と`role="tab"`を出力し、現在位置を`aria-selected`へ反映します。対応sectionには`role="tabpanel"`がなく、支援技術へ伝えるタブ操作モデルと実際の画面動作が一致しません。

SectionNavを通常のnamed navigationとページ内リンクとして表現し、現在位置が必要なら`aria-current="location"`を使うべきです。tab semanticsを維持する場合は一度に1つのtabpanelだけを表示する必要があり、このDiagnosticsの情報設計とは合いません。

## admin header分のscroll offsetが欠けている

**confirmed:** `app/frontend/entrypoints/application.css:1451-1453`はadmin内のSectionNavを`top: 45px`へ固定しますが、`app/frontend/controllers/section_nav_controller.ts:32-35`はtarget位置からnav自身の高さだけを引きます。最終的なsection topはnav高と同じ位置になるため、`45px..45px + nav高`を占めるsticky navと45px重なります。`.diagnostic-section { scroll-margin-top: 7rem; }`は、`preventDefault()`後に`window.scrollTo()`するこの経路には適用されません。

クリックでもheaderとnavを合わせた占有高を引くか、CSSの`scroll-margin-top`を正本にして`scrollIntoView()`へ寄せ、見出しがsticky要素の下に隠れないことをbrowser assertionにしてください。

## 新しい構造とcustom labelは自動テストで固定されていない

**confirmed:** `spec/frontend/admin_diagnostics_operational_failure_source_spec.rb`の変更は見出し名と`#failures`のsource文字列だけです。既存component specはdefault labelによる後方互換を確認しますが、custom `aria_label`、Diagnosticsの6 target、要対応countの内訳、Disclosure外のモデル概要は対象外です。

Component specへcustom labelを追加し、Diagnosticsのrendered responseで6つの`href`/target対応、内訳count、モデル概要とclosed Disclosureを確認してください。
